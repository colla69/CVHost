# DNS records for colarietitosti.info, mirrored from the Strato zone.
#
# Single source of truth, read by two things:
#   - infra/lib/dns-stack.ts       creates them in Route 53 via CDK
#   - scripts/aws-infra.sh verify  diffs them against live DNS before cutover
#
# Format, one record per line, '#' starts a comment:
#   name   TYPE   TTL    value          '@' = zone apex
#   @      MX     3600   10 mx.example.net.;20 mx2.example.net.     ';' separates values
#
# An unsupported TYPE throws at synth time rather than being skipped -- a record
# silently dropped here is a subdomain that goes dark at the nameserver cutover.
#
# Source: Strato panel, 2026-09-14. Apex A plus "Subdomains (8)". Confirmed from
# outside the same day: no AAAA, MX, TXT or CAA anywhere in the zone.

# The Strato box. Serves the apex redirect to admin, and every vhost below.
@     A      3600   85.214.103.161

# The wildcard, and it is load-bearing. Strato lists 8 subdomains and admin is
# NOT one of them -- yet admin.colarietitosti.info serves a live site with its
# own Let's Encrypt certificate and the apex redirects to it. So that list does
# not enumerate every working hostname, and anything relying on the wildcard
# that nobody remembers would go dark without this line.
*     CNAME  3600   colarietitosti.info.

# The 8 subdomains from the Strato panel, minus cv. Every one resolves to the
# box today and must keep doing so; only cv moves to AWS.

# These are redundant while the wildcard above exists -- it already answers them
# identically. They are listed anyway for two reasons: `aws-infra.sh verify`
# then checks each name individually before the cutover instead of trusting one
# wildcard probe, and naming every live host is the prerequisite for eventually
# dropping the wildcard. While that wildcard is there, a name cannot actually be
# retired: deleting its record just falls through to the wildcard.
